# v1 features: voice, Drive, todos and reminders

Silo v1 has three features beyond answering questions about files. Each one runs on the box
and keeps the user's data there.

1. **Voice conversation:** talk to it in English, and tap 🔊 on a reply to hear it.
2. **Google Drive downloads:** copy a shared folder, with everything inside it, into the user's files.
3. **Todos and reminders:** a todo list kept by voice or text, a morning list, and reminders
   at a time.

Every answer about data still goes through the checked path: io's Codex answers, the bridge's
own harness checks, and the reply carries a badge (`/how` shows the audit record). Todos and
Drive copies are logged in the same audit trail.

Commands in the menu: `/todos`, `/files`, `/drive`, `/model`, `/how`, `/reset`. Hidden: `/voice`.

## 1. Voice ↔ conversation

**What the user does:** sends a Telegram voice note in English, as they would to a colleague.

**What happens:**
1. The voice note is transcribed on the box by Whisper (`large-v3-turbo`, int8, on the CPU;
   a 17-second note takes about 5 seconds). The audio is never written to disk.
2. The bot shows the transcript straight away ("🎙️ “…”"), so the user can see what it heard.
3. The transcript is then handled exactly like a typed message: a todo command, small talk,
   a Drive link, or a question that goes to the checked answer path.

Two kinds of hint help with names:
- Whisper is given a glossary (`$SILO_CONFIG/glossary.txt`, e.g. "Swades Foundation",
  "Gadchiroli") and the user's open todos. Without the glossary it heard "Swades" as "SWAD's".
- The todo model is told the text may be a transcription with slips in names.

**Voice out: a 🔊 Read aloud button.**
- Every reply carries the button. Audio is made only when it's tapped, never ahead of time:
  short answers don't need it, but when the user is driving or on a bumpy ride, they'll tap
  it on the long ones.
- The audio is Kokoro on the CPU, about 6× real time, so a short reply arrives in about
  2 seconds. It reads ₹ amounts and Indian number words (lakh, crore) naturally.
- One read-aloud is made at a time per chat. A second tap on the same message, or a tap
  while one is being made, gets a short "already on its way" note instead of more audio.
  Speaking every reply to a voice note without a tap backed the box up, so it stays off
  (`VOICE_REPLIES=0`).
- The voice is called **Silo**: Kokoro's Hindi voice `hf_alpha` reading English, which gives
  an Indian accent ("Hi, this is Silo").
- `/voice` is a hidden command, not in the menu. It picks the voice per chat and plays a
  short sample. The choices are Silo; Heart, Bella and Michael (US); Emma and George
  (British); and Omega (Indian, man).
- Next to evaluate: asking for audio in the message itself ("send me an audio reply"),
  instead of tapping.

**Why the CPU:** the GB10's memory is shared between the CPU and GPU, and the model server
already uses most of it. Earlier GPU contention froze the box (`../GPU_COORDINATION.md`), so
speech stays on the CPU, where it's fast enough.

**Not in v1:** Indic languages; Whisper handles Hindi and Marathi, but nothing is tuned or
tested for them.

## 2. Google Drive downloads

**What the user does:**
1. `/drive` shows how to share a folder, then the bot's email in a separate message, tap to copy:
   `drive-silo@bitrot-in.iam.gserviceaccount.com`.
2. In Drive, they share the folder with that email as a Viewer.
3. They paste the folder's link into the chat.

**What happens:**
- The bot copies that link and nothing else, including every folder inside it, into the
  user's files.
- Google's own formats are converted: Sheets → `.xlsx`, Docs → `.md` (or `.txt`),
  Slides → `.pdf`, Drawings → `.png`.
- Forms and shortcuts are skipped and listed.
- `_drive_manifest.csv` records each file's Drive link, owner and last change.
- Limits: 500 MB and 2,000 files per link.
- First live run: the user's "Cell Ag" folder copied as 13 files in 5 folders (1.7 MB) in 22 seconds.

**What the user then does:**
- Ask questions about it; Codex and the checker both read the copy.
- `/files` lists their files like `ls`, with buttons to open folders and go up.
  `/files Cell Ag/Tufts` opens a folder directly. Nothing outside their own files can be listed.
- To refresh the copy, paste the link again.
- `/reset` deletes it.
- To revoke access, remove the email in Drive's Share dialog.

**Why a service account and not "Sign in with Google":** both are built. The bot uses the
service account when its key is present (`$SILO_CONFIG/drive_sa.json`), and falls back to
sign-in only if there's no key.

| | Sign in with Google | Service account (v1) |
|---|---|---|
| Admin work per user | Add their Gmail to the app's test-user list | None |
| What the user does | Sign in each time they want a copy | Share the folder once |
| Warnings the user sees | "Unverified app", then "see and download all your Google Drive files" | None |
| What Silo can read | All of that user's Drive, for a few seconds | Only what has been shared with it |

Leaving Google's "Testing" mode for sign-in needs verification, which for Drive read access
includes a paid security assessment.

**Privacy:**
- Only `drive.py` talks to Google. The agents that answer questions still have no network;
  they read the local copy.
- The service account's token is read-only and lasts an hour, and it's signed with the
  `openssl` command from a key that only the bot's user can read.

**Known gaps:**
- Anyone on the bot's allowlist who has a link the account can read can copy it. The fix
  would be to tie each Telegram user to a Gmail address and check who shared the folder.
- Word files (`.docx`) are copied as they are. The checker's sandbox has no Word reader
  (`.docx` is zipped XML, so it can still be read with `zipfile`). Converting to `.md` while
  copying would help both harnesses.
- A Google Workspace organisation that blocks sharing outside its domain won't let its
  users share with the account.

## 3. Todos and reminders

**What the user does, by voice or text:**
- "I just met Swades Foundation; I need to update the funds tracker. Add to my todos."
- "What are my todos?" or `/todos`.
- "I already did 1 and 2", or "I already updated the Swades funds tracker".
- "Remind me at 6 to call Meera."
- "Send my list at 8 every morning."
- "Cancel my reminders."

**How it works:**
- One call to the local model (Muse, with reasoning set low) turns the message into tool calls:
  `add_todos`, `complete_todos`, `delete_todos`, `edit_todo`, `show_todos`, `remind_at`,
  `set_daily_time`, `cancel_reminders`, `small_talk`, or `not_about_todos`.
- The bot carries out the calls itself and writes the confirmation from the database, so
  the list it shows is always the real one.
- Several calls in one message work ("add X and remind me at 6").
- Small talk ("thanks", "ok") gets a quick reply without the full answer path. Anything
  else goes to the checked answer path.
- Times are IST. A bare hour from 1 to 7 means pm, so "at 6" is 6 pm. A time that has
  already passed today means tomorrow.
- A reminder about something is also added to the todo list, unless the list already has
  it. When the reminder fires and the todo is still open, it says so and asks the user to
  say when it's done.
- Storage is SQLite on the box (`$SILO_DB`). `/reset` deletes the user's todos, reminders
  and settings, and compacts the file so the deleted rows are gone from disk too.

**What a reminder is:** the bot sends the user a Telegram message at that time, without
being asked.
- A Telegram bot may message anyone who has started a chat with it.
- A loop in the bot checks the database every 30 seconds:
  - Each day after the user's morning time (`TODO_DAILY`, default 09:00 IST), it sends the
    morning list ("☀️ Good morning! Your todos for today: …"), if there are open todos.
  - It sends any one-off reminder whose time has come ("⏰ Reminder: call Meera").
- Each message is marked sent, so it goes out once.
- If the bot is down at that moment, the message goes out when it comes back.
- Tested live: a reminder set 2 minutes ahead arrived on time.

**Measured:**
- The todo phrases above were understood 9 out of 9 times.
- A small-talk reply takes about 7 seconds, against about 20 seconds through the full path.

## What isn't in v1

- Audio asked for in words, instead of the button.
- Indic languages.
- Calendar and meetings.
- Linking Telegram users to Gmail accounts.
- Refreshing Drive copies on a schedule.
- `.docx` conversion.
