# Decode speed: smaller quant and a drafter

Local Muse Q8 decoded at 7.4 tok/s; a Telegram data question took about 400 s.
Decode on a dense 30B is limited by memory bandwidth (~273 GB/s on GB10), so
two levers were tried: fewer bytes per token (smaller quant), and more tokens
per pass (speculative decoding with a DFlash drafter, a ~3B model trained to
predict Muse; Muse verifies every drafted token, so output is unchanged).

Downloaded: `UD-Q6_K_XL` (26 GB), `UD-Q4_K_XL` (16 GB), drafters
`dflash-...-Q8_0` (bartowski) and `dflash-...-Q4_K_M`. `tg-bridge/serve_muse.sh`
restarts the server with any combination; `tg-bridge/bench.py` measures speed.

| setup | tok/s | harness eval (22) | eval wall, 2 parallel |
|---|---|---|---|
| Q8 | 7.4 | 11/11 (1 trial) | — |
| Q8 + drafter | 21.3 | 22/22 | 1270 s |
| Q6 + drafter | 22.9 | 22/22 | 1298 s |
| Q4 | 12.8 | 22/22 | 2061 s |
| Q4 + drafter | 35.5 | 22/22 | 937 s |

Drafter window: 16 beat 8 (21.5 vs 19.4 tok/s on Q8). Deployed: Q4 + Q4_K_M
drafter, `--spec-draft-n-max 16`. The same Telegram question now takes 67 s and
is correct. Correctness is measured on one clean synthetic workbook only.
Evidence: `benchmarks/decode-speed/`, `benchmarks/ngo-workbook-correctness/runs/2026-10-11-quant-drafter-sweep/`.
