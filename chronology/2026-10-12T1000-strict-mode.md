# Strict mode: the independent check is opt-in

**Asked:** "add a strict mode in the menu (/strict) that turns on correctness checking and
default it to off." This replaces always running the checker. Before this, the checker ran
on every real question and was thrown away when the answer had no single value, which cost
2 of the 4 model slots per question.

**Built:**
- `todos.py`: a `users.strict` column, added by migration and defaulting to 0, with
  `strict(user)` and `set_strict(user, chat, on)`. `/reset` deletes the users row, so it
  goes back to off.
- `answer.respond(..., strict=False)`:
  - **Off:** Codex alone, then the badge "➖ Not checked. /strict turns on independent
    checking." If Codex returns nothing, the bridge's harness answers instead. The audit
    record has `checker_status: "off"`.
  - **On:** unchanged: both run in parallel, compared, with a 30 s grace period.
- `tg_bridge.py`:
  - `/strict` shows the state with a Turn on/off button. It's in the menu as "Check every
    answer twice".
  - The "⏳ Working on it" message gives a time that matches the mode.
- `audit_log.how`: prints "Independent check: off (…)" when strict mode is off.
- Docs (README, deployment, the v1 narrative) now describe checking as opt-in.

**Tested live:** the question was "How many .docx files are in the Cell Ag folder, counting
all subfolders?"
- Off: answer 11 in 18.4 s, badge ➖; `/how` says the check is off.
- On: badge ✅ Verified.
- Then I turned it back off for the user.
